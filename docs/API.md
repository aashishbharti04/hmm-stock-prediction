# API Reference

Base URL (local): `http://localhost:8000/api/v1`

Interactive docs are auto-generated by FastAPI:
- Swagger UI → `http://localhost:8000/docs`
- ReDoc → `http://localhost:8000/redoc`

---

## Operational endpoints

| Endpoint            | Purpose                                                |
|---------------------|--------------------------------------------------------|
| `GET /health`       | Liveness probe — process is up.                        |
| `GET /ready`        | Readiness probe — `hmmlearn`, cache backend, metrics.  |
| `GET /metrics`      | Prometheus exposition (not under `/api/v1`).           |
| `GET /api/v1/cache/stats` | Cache hit/miss counters.                         |

Every API response carries an `X-Request-ID` (correlation id, echo it back to
trace a call across logs) and `X-Response-Time-ms`. Rate-limited endpoints also
return `X-RateLimit-Limit` / `X-RateLimit-Remaining`.

```json
// GET /health
{ "status": "ok", "version": "2.0.0", "environment": "development" }

// GET /ready
{ "status": "ok", "hmmlearn": true, "cache_backend": "memory", "metrics": true }
```

### Authentication (optional)

Auth is **off by default**. Set `API_KEYS` (comma-separated) on the backend to
require an `X-API-Key` header on `POST /analyze`, `POST /backtest` and
`POST /cache/clear`. A missing/invalid key returns `401`.

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
  -H "X-API-Key: $MY_KEY" -H "Content-Type: application/json" \
  -d '{"ticker":"AAPL"}'
```

## `POST /analyze`

Fetch market data, fit a Gaussian HMM, and return regimes + forecast. Results
are cached by request parameters (TTL configurable; `cached: true` on a hit).

### Request body

| Field                 | Type   | Default | Constraints                                   |
|-----------------------|--------|---------|-----------------------------------------------|
| `ticker`              | string | —       | 1–12 chars: `A–Z`, `0–9`, `.`, `-` (required) |
| `period`              | string | `2y`    | `1mo,3mo,6mo,1y,2y,5y,10y,max`                |
| `interval`            | string | `1d`    | `1d,1wk,1mo`                                   |
| `n_states`            | int    | `3`     | `2 ≤ n ≤ 8`                                    |
| `forecast_days`       | int    | `5`     | `1 ≤ d ≤ 30`                                   |
| `auto_select_states`  | bool   | `false` | Choose `n_states` automatically via BIC/AIC   |
| `selection_criterion` | string | `bic`   | `bic` or `aic` (when auto-selecting)          |

```json
{
  "ticker": "AAPL",
  "period": "2y",
  "n_states": 3,
  "forecast_days": 5,
  "auto_select_states": false,
  "selection_criterion": "bic"
}
```

  "interval": "1d",

### Error responses

| Status | Meaning                | When                                            |
|--------|------------------------|-------------------------------------------------|
| `422`  | Unprocessable Entity   | Invalid input, or too few observations to fit   |
| `404`  | Not Found              | No market data for the ticker (fallback off)    |
| `500`  | Internal Server Error  | Model failed to fit / unexpected error          |

```json
{ "detail": "Ticker must be 1–12 chars: letters, digits, '.', '-' only." }
```

## `GET /analyze`

Convenience wrapper using query parameters (handy for links/demos):

```
GET /api/v1/analyze?ticker=MSFT&period=1y&n_states=3&forecast_days=5&auto_select_states=true
```

Same response shape as the POST endpoint.

## `POST /backtest`

Run an **expanding-window walk-forward** evaluation of the one-step forecast and
report out-of-sample skill versus a naive baseline.

### Request body

Extends the `/analyze` body with:

| Field       | Type | Default | Constraints              |
|-------------|------|---------|--------------------------|
| `stride`    | int  | `5`     | `1 ≤ s ≤ 20` (days/fold) |
| `max_folds` | int  | `40`    | `5 ≤ f ≤ 120`            |

### Response `200` — `BacktestResponse`

```jsonc
{
  "ticker": "AAPL",
  "n_states": 3,
  "folds": 40,
  "directional_accuracy": 0.55,   // share of correct up/down calls
  "baseline_accuracy": 0.52,      // naive "always up" reference
  "rmse": 3.21,                   // price error magnitude
  "mape": 0.018,                  // mean abs. percentage error
  "points": [
    { "date": "2025-02-03", "actual_close": 181.2,
      "predicted_close": 180.4, "correct_direction": true }
  ]
}
```

## Examples

**curl**

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
  -H "Content-Type: application/json" \
  -d '{"ticker":"AAPL","period":"2y","n_states":3,"forecast_days":5}'
```

**JavaScript (fetch)**

```ts
const res = await fetch('http://localhost:8000/api/v1/analyze', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ ticker: 'AAPL', period: '2y', n_states: 3, forecast_days: 5 }),
});
const data = await res.json();
```

**Python (httpx)**

```python
import httpx
r = httpx.post("http://localhost:8000/api/v1/analyze",
               json={"ticker": "AAPL", "period": "2y", "n_states": 3, "forecast_days": 5})
print(r.json()["latest_state_label"])
```
